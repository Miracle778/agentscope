## 二、AgentScope 的设计哲学

读源码前先抓住一句话（README 原意）：

> 随着模型越来越强，框架应该用**精简的核心抽象**去适配模型，而不是用严格的 prompt 和固定的编排去约束模型。

这句话解释了你在源码里会反复看到的几个选择：

- **统一的 `Msg` + `ContentBlock` 体系**，而不是直接用 OpenAI 的 message dict——因为要适配 9 个 provider，每家格式不同。
- **中间件洋葱模型**，而不是固定的 agent 编排——把"记忆、预算、追踪、权限"都做成可插拔的 hook，框架只提供骨架。
- **ReAct 循环 + 事件流**，而不是一次性 prompt-completion——agent 是一个流式状态机，前端能逐 token 渲染、能在工具调用时暂停等人确认。
- **服务化与多租户**放在 `app/` 子包——库本身（`Agent` 类）能在单进程跑，也能被 FastAPI 服务化，跨进程靠 message bus。

理解了这几点，源码的"为什么这么写"就清楚了。

## 三、源码目录地图

```
src/agentscope/
├── message/      ① 消息与内容块（一切的基础）
├── agent/        ② Agent 主循环 ReAct + 上下文压缩（核心，最大文件）
├── model/        ③ LLM Provider 适配（9 家）
├── formatter/    ③ 消息格式化（每家一套）
├── credential/   ③ 凭据管理
├── tool/         ④ 工具系统（Toolkit / 内置工具 / MCP）
├── permission/   ⑤ 权限引擎 + Bash 静态分析
├── middleware/   ⑥ 中间件 hook（记忆/预算/追踪/...）
├── event/        ⑥ 事件总线（26 种事件）
├── state/        ⑦ AgentState 持久化载体
├── workspace/    ⑦ 沙箱（Local/Docker/E2B）+ 上下文 offload
├── mcp/          ⑦ MCP 客户端
├── embedding/    ⑦ 嵌入模型（供记忆用）
├── app/          ⑧ 服务化（FastAPI / 多租户 / 调度 / 消息总线）
└── _utils/       工具函数
```

## 四、建议阅读顺序（由浅入深）

```
第1章 消息与内容块  ──→  理解 Msg/ContentBlock，这是所有模块的"货币"
        │
第2章 ReAct 主循环  ──→  理解 agent 怎么"想一步做一步"，整个框架的心脏
        │
第3章 模型与格式化  ──→  理解统一 Msg 如何变成各家 API 请求
        │
        ├──→ 第4章 上下文压缩 ──→ 第2章的进阶，上下文超了怎么办
        │
        ├──→ 第5章 记忆系统   ──→ 短期/长期/跨 agent 三层记忆
        │
        ├──→ 第6章 工具系统   ──→ 工具怎么注册/分发/并发
        │
        └──→ 第8章 权限系统   ──→ 工具调用前的安全闸门

第7章 多 agent 调度 ──→  团队/消息总线/唤醒/后台任务（需要先懂 2/6）
第9章 中间件与事件  ──→  把前面所有 hook 串起来看
第10章 服务化       ──→  单进程 → 多租户服务的跃迁
```

**最快的入门路径**：先读第 1、2 章，能跑通一个最小 agent；再按兴趣深入。

## 五、调试与实验建议

1. **跑 example**：`examples/` 下有 web_ui、agent_service、long_term_memory 三个完整示例，先跑通 web_ui 直观感受事件流。
2. **打断点**：在 `agent/_agent.py` 的 `_reply_impl`（`:541`）打断点，看一次完整回复的所有中间状态。
3. **看测试**：`tests/` 下的测试文件几乎是"活文档"，比如 `permission_engine_test.py` 把权限语义讲得比 docstring 还清楚。每个模块对应的 `xxx_test.py` 是最佳学习材料。
4. **画状态图**：`ToolCallState`（PENDING/ASKING/ALLOWED/SUBMITTED/FINISHED）的状态转换是理解 HITL（人在环中）的关键，建议自己画一遍。
